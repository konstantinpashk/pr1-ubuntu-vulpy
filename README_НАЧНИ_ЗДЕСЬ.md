# ПР1 — Ubuntu / Vulpy (вариант № 1)

**Проект:** https://github.com/fportantier/vulpy (MIT, образовательный уязвимый Python/Flask-проект).  
**Объект проверки:** `source/vulpy/bad` — специально небезопасная реализация.  
**Инструменты:** Ubuntu, Bash, Git, Bandit, Python 3.  
**Никогда не запускай уязвимое веб-приложение в общедоступной сети.** Его запуск для ПР1 не нужен.

## Порядок работы (Ubuntu)

1. Распакуй папку `PR1_Vulpy_Ubuntu` в домашнюю директорию Ubuntu, открой терминал. Команды выполняются **в корне распакованной папки**, там, где лежат `01_setup_ubuntu.sh` и `02_scan.sh`.
2. Выполни:

```bash
cd ~/PR1_Vulpy_Ubuntu
bash 01_setup_ubuntu.sh
bash 02_scan.sh
```

Сценарий 1: устанавливает необходимые пакеты Ubuntu (через `apt`), клонирует оригинальный код **во временную папку**, копирует его в `source/vulpy/` без вложенной `.git`, сохраняет SHA коммита, создаёт Python venv и устанавливает только инструменты анализа. **Зависимости уязвимого веб-приложения НЕ устанавливаются.**

Сценарий 2: анализирует `bad/` и для сравнения `good/` с помощью Bandit. Bandit обычно возвращает exit code 1 при наличии находок — это штатный результат, не ошибка выполнения. Сохраняются JSON/CSV, статистика и отчёт DOCX, сформированный уже по реальному сканированию.

3. Создай на GitHub **пустой приватный репозиторий**, например `pr1-ubuntu-vulpy`. Не ставь галочки «создать README/.gitignore/license», чтобы не получить конфликт при первой отправке.
4. Настрой имя и email для Git (один раз):

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "mail@example.com"
```

5. Публикация из Bash (замени USERNAME своим логином):

```bash
bash 03_publish_github.sh https://github.com/USERNAME/pr1-ubuntu-vulpy.git
```

GitHub не принимает пароль аккаунта для `git push` по HTTPS — используй подходящую аутентификацию GitHub (например, Git Credential Manager / токен). Можно использовать SSH-URL, если SSH уже настроен.

## Артефакты

- `reports/ПР1_отчет_предварительный.docx` — предварительный отчёт с **ручным** анализом (не притворяется результатом Bandit).
- `reports/ПР1_отчет_по_сканированию.docx` — **появится после запуска** `02_scan.sh` и будет содержать фактические результаты Bandit.
- `datasets/Ручной_аудит_Vulpy.csv` и `.json` — 12 выводов из исходных файлов с указанием источника.
- `datasets/Ручной_аудит_Vulpy.xlsx` — красиво оформленный датасет для сдачи.
- `datasets/bandit_bad.csv`, `datasets/bandit_good.csv` — **будут созданы** при сканировании.
- `reports/bandit_bad.json`, `reports/bandit_good.json` — исходные отчёты сканера после запуска.
- `reports/summary.json`, `reports/Актуальные_результаты.md` — подсчёт находок по severity после запуска.
- `metadata/upstream_commit.txt` — SHA зафиксированной версии исходного проекта после клонирования.

## Что показать преподавателю (скриншоты делай у себя)

- `lsb_release -a`, `git --version`, `python3 --version`;
- `pwd && ls -la` после распаковки и клонирования;
- вывод `bash 02_scan.sh`, файл `reports/Актуальные_результаты.md`;
- `git remote -v && git log -1 --oneline && git status` и созданный репозиторий в браузере GitHub.

## Методика и честность результатов

12 строк ручного анализа подтверждены просмотром исходных файлов на GitHub, но они **не** являются 12 срабатываниями Bandit. Не все виды уязвимостей (например, XSS, CSRF) находятся Bandit. Факт срабатывания, число предупреждений и сравнительные показатели BAD/GOOD становятся известны только после запуска в Ubuntu. Экспертный риск — оценка по свойствам кода, **не рассчитанный CVSS**.
